Data modeling for AI — the decision engine base

A dimensional model where a new engine enters as one row, not as a schema change.

Franq Open Banking2026
65columns untangled
1row to add an engine

The problem

The engine table had 65 columns and did not say which were rule inputs, which were the engine decision and which were the commercial outcome. Every question became a new query, and two people reached two different numbers for the same metric.

What I built

A dimensional model in dbt fixing three contracts: the grain, the role of each variable and what a missing value means. The core is engine-agnostic — facts for the decision and for the product offered, a bridge table holding inputs as rows rather than columns, and point-in-time tables for the sources that must be read as they were on the day.

Result

Tested against a second engine: adding it needs one row in the engine dimension and nothing else. The same base now answers analytics questions and feeds ML features.
